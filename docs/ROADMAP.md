# WebRop 三阶段发展方案

## 总览

```
阶段一：连接 ROS（跑通基础链路）
    ↓
阶段二：对接 HoloLens（获得空间感知能力）
    ↓
阶段三：VLM / 空间理解（语义升级）
```

每一步是下一步的基础：ROS 没连上就无法验证 HoloLens 发的数据；没有 HoloLens 的 Spatial Mapping 就没有 3D 点云输入给 VLM 做语义理解。

---

## 阶段一：连接 ROS — 让 Web 端真正控制机器人

### 1.1 现状

代码里 ROS 通信框架已搭好（`src/ros/connection.ts`），支持：

- 订阅 `/map`（OccupancyGrid）、`/odom`（Odometry）、`/move_base/NavfnROS/plan`（Path）
- 发布 `/move_base_simple/goal`、`/cmd_vel`、`/waypoint_goals`、`/hrz_zones`、`/hrp_path`、`/hrp_speeds`

但存在两个问题：

**问题 A：ros1_bridge 节点是半成品**

- `hrz_costmap_node.py`：收到 HRZ 禁区数据后只打了 log，没有把多边形写入 costmap
- `hrp_planner_node.py`：收到 HRP 路径后直接转发，没有和 move_base 对接做真正的路径规划

**问题 B：没有经过真机验证**

所有功能都在 Mock 模式下运行（A* 模拟、差速驱动模拟），还没接上真实的 ROS master + 机器人。

### 1.2 目标

Web → rosbridge → ROS 1 → 机器人，这条链路完整跑通。

### 1.3 具体工作

#### 1.3.1 搭建 ROS 1 环境

- 安装 ROS 1 Noetic（Ubuntu 20.04）或 Melodic（Ubuntu 18.04）
- 启动 `roscore` + `rosbridge_server`（默认端口 9090）
- 启动机器人驱动节点（底盘、激光雷达）
- 启动 `move_base`（配置 costmap 参数、全局/局部规划器）

#### 1.3.2 补完 hrz_costmap_node

当前节点只接收禁区 JSON 并打 log。需要实现：

1. 解析禁区 JSON，提取多边形顶点列表
2. 根据禁区等级（禁止/慢速/充电）设置 cost 值
3. 将多边形光栅化到 costmap 对应区域
4. 作为 `move_base` 的 costmap plugin（或发布更新后的 costmap 到 `/hrz_costmap`，由 `move_base` 订阅）

关键接口：

```
输入：/hrz_zones (std_msgs/String) — JSON 格式的禁区列表
输出：/hrz_costmap (nav_msgs/OccupancyGrid) — 更新后的 costmap
```

禁区等级与 cost 值映射：

| 等级 | cost | 含义 |
|------|------|------|
| 禁止 (forbidden) | 254 (lethal) | 绝对不可通过 |
| 慢速 (slow) | 128 | 代价高，尽量绕行 |
| 充电 (charging) | 200 | 接近禁止，仅充电任务可进入 |

#### 1.3.3 补完 hrp_planner_node

当前节点收到路径后直接转发。需要实现：

1. 接收 HRP 路径（`/hrp_path`）和分段速度（`/hrp_speeds`）
2. 获取机器人当前位姿，将起点拼接到路径头部
3. 将参考路径发布为 `/hrp_global_plan`（`nav_msgs/Path`）
4. 和 `move_base` 的全局规划器集成：
   - 方案 A：替换 NavfnROS，HRP 路径直接作为全局规划结果
   - 方案 B：HRP 路径作为 NavfnROS 的初始种子，规划器在种子附近微调
5. 根据分段速度发布速度指令或调整局部规划器参数

关键接口：

```
输入：/hrp_path (nav_msgs/Path) — 参考路径
输入：/hrp_speeds (std_msgs/String) — 分段速度 JSON
输入：/odom (nav_msgs/Odometry) — 机器人位姿
输出：/hrp_global_plan (nav_msgs/Path) — 全局规划路径
```

#### 1.3.4 端到端验证

验证场景：

1. **导航**：Web 端点击地图 → 发布目标 → 机器人移动到目标点
2. **禁区**：Web 端画 HRZ 多边形 → costmap 更新 → 机器人绕行
3. **路径**：Web 端画 HRP 路径 → 全局规划器使用参考路径 → 机器人沿路径走
4. **遥控**：Web 端 WASD → cmd_vel → 机器人实时响应

#### 1.3.5 位姿同步

当前 `poseSyncStore` 提供了独立 WebSocket 服务器（端口 9091），用于多机器人位姿收发。需要：

- 部署 WebSocket 中继服务器
- 多机器人场景下各机器人位姿通过 rosbridge 订阅各自 `/odom`，汇总后广播

### 1.4 预计产出

- 完整的 ROS 1 launch 文件（`web_bridge.launch` 已有框架，需补充）
- 可用的 `hrz_costmap_node` + `hrp_planner_node`
- 真机验证报告（导航/禁区/路径/遥控四项功能）

## 阶段二：对接 HoloLens — 从浏览器延伸到混合现实

### 2.1 背景

两篇论文（MRHaD、MRReP）原文是 HoloLens + Unity 实现的，本项目改成了 Web 版。对接 HoloLens 不是移植，而是让 HoloLens 成为 WebRop 的**前端之一**，和 Web 端共享数据。

### 2.2 架构

```
HoloLens (Unity/C#)
    ↕ WebSocket / REST API
WebRop Server (Node.js / Python)
    ↕ WebSocket (rosbridge)
ROS 1 (move_base, 机器人驱动)
```

两端共享：地图、禁区、路径、机器人位姿。

### 2.3 HoloLens 端工作

#### 2.3.1 Spatial Mapping → 自动禁区

HoloLens 的 Spatial Mapping 持续扫描环境，生成 3D mesh。将这些 mesh 投影到 2D costmap：

1. 获取 Spatial Mapping mesh 数据
2. 按 Z 轴高度做截面，提取地面以上 N cm 的障碍物轮廓
3. 将轮廓光栅化为 OccupancyGrid 格式
4. 通过 WebSocket 发给 WebRop Server → 转发到 ROS `/map` topic

手绘禁区变为补充手段：只画 Spatial Mapping 漏掉的或语义层面的禁区（如"这片区域人流量大"）。

#### 2.3.2 动态禁区 — 人体检测

HoloLens 前方摄像头检测到人：

1. 识别人体位置和朝向
2. 在 costmap 中生成临时禁区（持续时间可设）
3. 人离开后自动消除
4. WebRop 3D 场景中用半透明蓝色气泡标注检测到的人

这解决了论文实验中提到的"行人干扰"问题。

#### 2.3.3 手势 + 语音交互

- 手势画禁区/路径（论文已有）
- 语音补充："删除这个禁区"、"从这里开始画"、"发送给机器人"
- 语音+手势组合：看着某个禁区说"扩大一点"，手势 pinch 拖拽调整范围

#### 2.3.4 眼动追踪选区

HoloLens 2 的眼动追踪：注视某个已有禁区 1 秒 → 高亮选中 → 手势删除或调整。比"点击顶点删除"更自然。

#### 2.3.5 空间锚点多用户共享

通过 Azure Spatial Anchors：

- 一个用户画完禁区/路径后分享给另一台 HoloLens
- 两人同时看到同一组禁区/路径，一人调整另一人实时同步
- 多机器人多操作员场景

### 2.4 虚实融合

#### 2.4.1 机器人意图可视化

机器人规划的路径投射到物理地面上（绿色光线），和手绘参考路径（蓝色光线）同时可见。偏差一目了然。

#### 2.4.2 机器人状态全息 HUD

看向机器人时，视野中出现浮动信息卡：电池电量、当前速度、导航状态、前方障碍物距离、预计到达时间。

#### 2.4.3 路径预演动画

画完路径后说"预演"，半透明全息机器人沿路径走一遍，速度等于实际导航速度。用户站在物理空间中观察是否撞墙、转弯是否自然，确认后再发真实导航命令。

#### 2.4.4 空间音频

- 机器人接近禁区边界 → 空间音频从禁区方向发出低频警告音
- 导航完成 → 从机器人方向发出确认音

### 2.5 WebRop Server 端工作

需要一个中间层处理 HoloLens ↔ ROS 的数据转发：

1. WebSocket 服务器，接受 HoloLens 和 Web 端同时连接
2. 数据同步：禁区/路径/位姿变更广播给所有连接的客户端
3. 坐标系对齐：HoloLens 空间坐标 ↔ ROS map 坐标 ↔ WebRop 场景坐标的转换
4. Spatial Anchors 管理和分发

### 2.6 预计产出

- HoloLens Unity 项目（Spatial Mapping、手势、语音、眼动追踪）
- WebRop Server 中间层（WebSocket 中继、数据同步、坐标转换）
- WebRop Web 端增加 HoloLens 数据接入（动态禁区、3D mesh 叠加）
- 双端联合验证报告

### 2.7 优先级

最值得做的组合：**动态人体禁区 + 意图可视化 + 路径预演**

- 动态人体禁区解决论文最大的实际痛点（行人干扰）
- 路径预演 + 意图可视化把"画完就发"变成"画完→预演→确认→发"，大幅降低导航失败率
- 这三个组合起来就是论文工作的 2.0 版本

## 阶段三：VLM / 空间理解 — 从几何避障到语义导航

### 3.1 核心跃迁

```
当前：这里是墙 / 这里是空地（二值 OccupancyGrid）
升级：这是可推开的椅子、这是人坐着的沙发、这是玻璃门、这是台阶边缘

从"几何避障"到"语义导航"。
```

### 3.2 技术路线

```
RGB-D / 点云 → 3D 检测/分割模型 → 语义标注 → 语义 costmap → 语义路径规划
                                ↓
                        自然语言交互 → 变更检测 → 自适应导航
```

可选模型方案：

| 方案 | 输入 | 输出 | 特点 |
|------|------|------|------|
| 3D-LLM / Point-E | 点云 + 文本 | 3D 语义标注 | 端到端理解 |
| SAM + CLIP | RGB-D | 分割 + 语义标签 | 成熟稳定 |
| GPT-4V / LLaVA | RGB 图像 | 物体描述/指代 | 通用 VLM |
| 空间理解模型（ScanNet 等） | 点云 | 场景分区/物体边界 | 室内场景专用 |

### 3.3 语义禁区 — 自动生成

#### 3.3.1 物体级禁区自动标注

点云 + RGB 识别出场景中每个物体，用户看到的是 3D 标注："椅子""桌子""垃圾桶"。点击物体即可将其标记为禁区，不需要手动画多边形。

进阶：模型输出物体属性——"可移动""固定""易碎"——自动建议禁区类型：

- 椅子 → 黄色软禁区（可推开绕行）
- 承重柱 → 红色硬禁区
- 玻璃门 → 橙色警告禁区（看不见但存在）

#### 3.3.2 场景理解自动分区

模型识别出"走廊""房间""门口""楼梯"等空间语义，自动生成通行约束：

- 门口 → 自动添加窄通道约束，路径在此段收窄
- 楼梯 → 自动生成禁止区域（当前楼层机器人不可通过）
- 电梯 → 标注为可等待区域，路径可经过但需要停靠

#### 3.3.3 动态物体持续跟踪

人、推车、开门等动态物体被持续识别并分类：

- 站着的人 → 临时软禁区，5 秒无移动则升级为硬禁区
- 推车 → 软禁区 + 预测轨迹（虚线延伸），路径避开预测区域
- 开着的门 → 当前可通行，但标注"可能关闭"，路径预留关门后的备选

### 3.4 语义 costmap — 代价语义化

当前 costmap 只有 0-100 的占用值。升级为语义 costmap：

| 物体 | cost | 理由 |
|------|------|------|
| 承重墙 | 254 (lethal) | 绝对不可通过 |
| 玻璃门 | 200 | 看不见但存在 |
| 可推椅子 | 60 | 可推开但代价高 |
| 地面电缆 | 40 | 可能卡轮子 |
| 刚擦的湿地面 | 30 | 打滑风险 |
| 人背后 1m | 20 | 社交不适区 |

路径规划不再是纯几何最短，而是语义最优——宁可多走 2 米绕过人背后，也不从人正面 1 米处经过。

### 3.5 自然语言交互

#### 3.5.1 自然语言 + 点云指代

- "把那个垃圾桶周围设为禁区" — VLM 解析"那个垃圾桶"对应的 3D 区域，自动生成多边形
- "沿着窗户这边走" — 模型识别窗户位置，自动生成沿窗参考路径
- 手绘禁区变成自然语言指定 + 手势微调的组合

#### 3.5.2 变更检测提醒

当前帧点云与历史帧对比，检测到场景变化：

- 新增物体（有人放了箱子）→ 3D 中黄色高亮闪烁，提示"检测到新障碍物，是否标记禁区"
- 物体移走（椅子被搬走了）→ 原有禁区变灰，提示"该区域可能已畅通，是否移除禁区"
- 门状态变化 → 路径可行性自动更新

### 3.6 语义路径 — 智能参考

#### 3.6.1 物体感知路径建议

用户说"去厨房"，系统根据语义地图自动生成参考路径初稿，用户只需微调而非从零画起。3D 中用浅蓝色虚线显示建议路径，用户手势拖拽修改。

#### 3.6.2 社交意识路径

模型识别出人的朝向和活动（坐着办公、站着聊天、走路中），路径自动：

- 避开人的正面活动区域（尊重个人空间）
- 经过人的背后而非正面
- 在"人坐着办公"的区域自动加宽禁区边距（比如从 0.3m 扩到 1m）

3D 中用渐变色显示社交距离梯度。

#### 3.6.3 语义约束路径段

路径不同段落可标注语义约束：

- "静音段"：经过办公区，降速 + 禁止语音播报
- "窄通道段"：经过门口，收窄机器人足迹
- "等候段"：经过电梯口，路径中插入等待点

3D 中不同段用不同颜色/图标标注，HRP planner 按约束发布不同速度参数。

#### 3.6.4 路径可行度评分

画完参考路径后，系统基于语义 costmap 计算路径可行度评分（0-100%），3D 中沿路径用红→黄→绿渐变显示各段风险。低于 60% 的段自动标红，提示"此处可能无法通过：前方为玻璃门"。

### 3.7 多层地图管理

点云模型识别楼层，自动切换/叠加不同楼层的语义地图。用户在 3D 场景中可切换楼层，每层独立管理禁区和路径。跨层导航（电梯/楼梯）自动生成层间转移点。

### 3.8 预计产出

- 3D 语义标注模块（点云/RGB → 物体检测/分割 → 语义标签）
- 语义 costmap 生成器（物体 + 属性 → cost 值）
- VLM 自然语言交互接口（语音/文字 → 指代解析 → 禁区/路径生成）
- 变更检测模块（帧间对比 → 场景变化提醒）
- WebRop 3D 场景语义可视化（物体标注、可行度渐变、社交距离梯度）

### 3.9 优先级

最核心的组合：**物体级禁区标注 + 语义 costmap + 可行度评分**

这三个构成闭环：用户画路径 → 系统评估 → 高风险段提示原因 → 用户调整 → 重新评估。从"画完就发、碰运气"变成"画完即知、精确导航"。

## 里程碑时间线

| 阶段 | 主要工作 | 交付物 |
|------|---------|--------|
| **阶段一** | 连接 ROS | 补完 bridge 节点、真机验证通过 |
| **阶段二** | 对接 HoloLens | Unity 端 + Server 中间层 + 双端联调 |
| **阶段三** | VLM/空间理解 | 语义 costmap + 自然语言交互 + 可行度评分 |

阶段之间有依赖关系，但部分工作可以并行：阶段一后期就可以开始阶段二的 Server 中间层开发；阶段二的 Spatial Mapping 数据流跑通后就可以开始阶段三的点云处理。
